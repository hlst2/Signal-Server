Signal-Server (server-private)
==============================

This branch is a private fork of [Signal-Server][upstream] with all
externally-billable integrations removed. It is intended to run on a single
Debian host with no inbound or outbound dependencies on Signal's infrastructure
after the initial install.

**Removed from upstream:** Stripe, Braintree (incl. PayPal), Apple App Store
IAP, Google Play Billing, Apple DeviceCheck, the donations/subscriptions/
receipts/currency-conversion stack, and the Braintree Apollo GraphQL client.

**Retained from upstream:** registration, accounts, messages, profiles,
attachments, backups, key transparency, APN/FCM push, and Cloudflare TURN.

[upstream]: https://github.com/signalapp/Signal-Server

Quick start
-----------

The repo ships an installer that provisions everything in one online step,
then a wrapper that runs the server fully offline on every subsequent boot.

```sh
git clone <this-repo-url>
cd Signal-Server
sudo ./install-deps.sh        # one-time, requires internet
./run-local.sh                # every run after that, no internet required
```

After `./run-local.sh` finishes booting the server listens on HTTP `8080`
(admin port `8081`) and gRPC `50051`, with the stubs documented in
[TESTING.md](TESTING.md).

First run — online
------------------

[`install-deps.sh`](install-deps.sh) is idempotent and targets a fresh Debian
12 (bookworm) or 13 (trixie) host, amd64.

Run it once, as root, with internet access:

```sh
sudo ./install-deps.sh
```

What it installs and configures:

1. **System packages** — `ca-certificates`, `curl`, `gnupg`, `git`,
   `build-essential`, `unzip`.
2. **Eclipse Temurin JDK 25** via Adoptium's APT repo (matches
   [`.java-version`](.java-version)).
3. **Docker Engine + Compose plugin** from Docker's official APT repo, and
   adds the invoking user (via `$SUDO_USER`) to the `docker` group.
4. **FoundationDB client library 7.3.62**, with a SHA-256 check against the
   value pinned in [`pom.xml`](pom.xml).
5. **`spam-filter` submodule** — initialized if a real `submodule.spam-filter.url`
   is configured locally, otherwise the build is wired to use the
   `exclude-spam-filter` Maven profile.
6. **Maven local repository** (`~/.m2/repository`) — warmed with every build,
   test, and plugin dependency so that subsequent `mvnw` invocations can use
   `-o` (offline mode).
7. **Docker images** — pre-pulls the testcontainer images that the local
   server uses on startup (DynamoDB Local, Redis, Redis Cluster, LocalStack,
   FoundationDB, testcontainers ryuk reaper).
8. **`run-local.sh`** — generated wrapper that runs the server offline.

Re-run with `--skip-pull` or `--skip-warm` to skip the Docker pulls or Maven
warm if you already have them cached. Note that skipping either of those
breaks the offline guarantee on subsequent runs.

After the install completes, log out and back in (or run `newgrp docker`) so
the new group membership takes effect.

Subsequent runs — offline
-------------------------

Once `install-deps.sh` has finished successfully, the host is ready to run
the server without internet access. This works across reboots: nothing needs
to be re-fetched because Maven artifacts live in `~/.m2/repository`, Docker
images live in `/var/lib/docker`, and the FoundationDB client lives in
`/usr/lib`.

```sh
./run-local.sh
```

[`run-local.sh`](run-local.sh) is generated by `install-deps.sh` and runs:

```sh
./mvnw -o -Ptest-server,exclude-spam-filter integration-test -DskipTests=true
```

with a few environment overrides that prevent SDK metadata probes from
hanging on an isolated host:

| variable | value | reason |
| --- | --- | --- |
| `AWS_EC2_METADATA_DISABLED` | `true` | skips `169.254.169.254` IMDS probe |
| `NO_GCE_CHECK` | `true` | skips `metadata.google.internal` probe |
| `TESTCONTAINERS_RYUK_CONTAINER_IMAGE` | the pre-pulled tag | pins ryuk to a cached image |
| `TESTCONTAINERS_RYUK_DISABLED` | `true` *(fallback)* | set automatically if ryuk image isn't cached |
| `TESTCONTAINERS_CHECKS_DISABLE` | `true` | skips testcontainers' startup self-check |

Pass `--online` to `run-local.sh` to temporarily re-enable Maven network
access (useful after editing a dependency version). Any other args are
forwarded to `mvnw`.

How offline survives a restart
------------------------------

Nothing in `run-local.sh` is stateful per-boot. The pieces it depends on are
all persistent:

- `~/.m2/repository` — Maven's local artifact cache, warmed once during the
  install.
- `/var/lib/docker` — Docker image store. The pre-pulled testcontainer images
  live here.
- `/usr/lib/libfdb_c.so` — FoundationDB client library installed via `dpkg`.
- `/usr/lib/jvm/temurin-25-jdk-*` — Adoptium JDK installed via `apt`.

If a reboot interrupted `install-deps.sh` partway through, just re-run it —
every step is idempotent and skips work already done.

Verifying offline operation
---------------------------

To prove the host can actually run with no network, drop egress before
starting:

```sh
# block outbound IPv4 from the user that will run the server
sudo iptables -I OUTPUT -m owner --uid-owner "$USER" -j REJECT
./run-local.sh
```

The server should start as normal. Stubbed external services (CDS, SVR,
storage, registration, push, etc.) log DNS errors only when those code paths
are actually invoked, not at startup. Remove the iptables rule with
`sudo iptables -D OUTPUT -m owner --uid-owner "$USER" -j REJECT` when done.

Limitations of this fork
------------------------

`run-local.sh` starts `LocalWhisperServerService`, which is a feature-limited
test entry point — not the production `WhisperServerService`. In particular:

- **External Signal services are stubbed.** Contact Discovery, Secure Value
  Recovery, the storage service, key transparency, and the registration
  service do not actually run. SMS verification accepts any code and the
  captcha `noop.noop.registration.noop` always passes. See
  [TESTING.md](TESTING.md).
- **Storage is ephemeral.** DynamoDB and Redis are spun up inside Docker via
  testcontainers and discarded on every server restart. Account state does
  not persist across runs.
- **No donations or paid subscriptions.** Stripe, Braintree, Apple App Store,
  and Google Play Billing flows were stripped from this branch (see commit
  `3b7f28283`). The `redeemedReceipts` DynamoDB table is retained so
  `BackupAuthManager` compiles and runs, but it will always be empty in
  this configuration — every account is treated as free-tier for backups.
- **Push notifications and TURN are still wired** but call out to APNs, FCM,
  and Cloudflare. They are lazy and won't fire unless real credentials are
  supplied in [test.yml](service/src/test/resources/config/test.yml).

Running the production entry point (`WhisperServerService`) additionally
requires a real FoundationDB cluster (`apt install foundationdb-server`),
real Redis/DynamoDB/S3 backends, and credentials for every external service
that wasn't stripped — that setup is out of scope for `install-deps.sh`.
